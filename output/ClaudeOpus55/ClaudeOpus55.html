外部核不到的

  • 训练语料只披露成公开网络的专有混合，某道题进没进训练集只有厂商能判断。
  • Epoch 的审查框架里，「是否有污染证据」连它自己都标 Not reviewed；它要求披露的是 effort 档、token 与时间上限、工具权限和系统提示。

饱和之后，1–2 个点量不出谁更强

Epoch 抽查 HLE 的 48 题，22 题有足以改变正确性的错误，整条榜判为 Flawed。跑 5 次的 Opus 5.5 误差 ±2.6 点，跑 10 次与 15 次的对照模型只有 ±1.6–2 点——省钱的跑法误差条最宽。Terminal-Bench 给饱和下过可操作定义：最新一代每类模型都 5/5 做对，这题就没了区分力，删。发布页自己也降温：到这个档位，分数差距作为真实差异的指示已经不太可靠。

「贵了多少」必须连带四栏一起说：单价、上下文、缓存、限速

两类降价得分开说：单价降两成，典型账单降四成

Opus 5.5 的输入与输出单价是每百万 token 4 美元、20 美元，对应 Opus 5 的 5 美元、25 美元，降 20%；发布页同时称默认设置下典型负载比 Opus 5 便宜 40%。

差的二十个点不在价目表上，来自同一任务用的 token 变少。只转述 40% 会让人以为单价被砍近一半；只转述 20% 又低估账单的实际变化。

第四栏是限速：API 按分钟计，订阅按五小时计

API 限额按组织所在档位（Start、Build、Scale）设定，计量指标为每分钟请求数 RPM、每分钟输入 token ITPM、每分钟输出 token OTPM，超任意一项返回 429 并附 retry-after。档位自动分配，充值或购买不把你推上去；用到当前额度 50% 以上可在 Console 申请提额。各档具体数字只在 Console 与 API 文档表格里，本次网络打不开该页，不引用。

订阅侧是另一套口径：五小时会话限额加每周限额。发布页称这一版提高了 Pro、Max、Team 与席位制 Enterprise 的五小时限额，并给出可自行决定何时使用的 limit reset。

最容易漏的一栏

缓存读 $0.20 与输入 $4 差二十倍，官方称缓存读构成 agentic 与编码成本的大头，只报输入原价会把成本高估一个量级。也别把 40% 读成「更强还便宜一半」：它依赖每任务 token 数下降这一实测前提，而该数来自各家脚手架。本篇不下「哪家更划算」的结论。

预算从「答得快」挪到「想得久」：这改变了能力该怎么测

预算不是比喻，是写进请求体的一个参数

旧形态是 thinking.budget_tokens：下限 1,024 token，必须小于 max_tokens，文档写明它是「目标而非硬限制」。思考内容按输出 token 计费，max_tokens 又同时封顶思考与正文——预算挪一格，延迟、账单、截断风险一起动。2026-09-22 发布的 Claude Opus 5.5 换了旋钮：budget_tokens 在 Opus 4.6 上标记弃用，改用 adaptive 配 output_config.effort 五档（low／medium／high／xhigh／max）。AWS 档位表把 high 写成默认，发布页几处把 medium 写成 default effort。

定档：把「哪一档值得」变成一次可重复的实验

  1. 用自己的负载跑满五档只测默认档，你拿到的是一个点。每题记得分、成本、首字延迟。
  2. 先找便宜的验证器有判分脚本的，抬档买到搜索；只能靠人读的，买到篇幅。
  3. 别把省略当成关掉这一代省略 thinking 字段就跑自适应思考并按输出计费；要关得显式传 disabled。
  4. 把档名写进每条记录评测、报价、复盘都带 effort 值与日期；跨版本还要核对默认档是否同名。

值得抬这一档

  • 跨文件长链条改动：整库迁移、代码审计
  • 边调工具边推理的流程（自适应档会一并打开 interleaved thinking）
  • 结果能被外部程序验收：回归测试、财务模型

不值得抬档

  • 单跳事实问答、格式转换、字段抽取
  • 延迟被 SLA 卡死的在线路径
  • 验收只能靠「读起来顺」的任务
分界不是题目难不难，而是有没有便宜的验证器。

默认值不是常量

上一代省略参数意味着不思考，这一代意味着自适应思考并开始计费。请求体没改，账单多出一段思考 token。上线前用自己的负载量一遍。

长任务真正的断点不在智力，在上下文、错误恢复和工具

「跑得久」和「干得难」是两个轴

先分开两件事：跑了多少小时与多少步，和任务本身有多难。

METR 的「时间地平线」把长度换算成难度：50% 时间地平线＝「模型有一半概率做对的那类任务，人类专家要花多久」，量难度而非模型耗时。跑法：每任务 6 次独立 run、各设 token 与时间上限，并人工筛查作弊式通过。同一家提醒：8 小时地平线对照的是无背景知识的新人，不是老手。

清单之外的那句方法论

收尾一条纪律：一个发布能改变的是「带口径的观测」，改变不了「关于能力的判断」。前者是可复现的数，连着子集、预算、脚手架、判分方式；后者要多任务分布、多时点、多家独立复现才敢松动。第三方也照这个规矩立标准：成本按每任务实际消耗的 token 计，不按标价。
