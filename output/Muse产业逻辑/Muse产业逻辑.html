钱分给四层，但价格结构不对等

再看付给谁。一句话背后大致过四层：模型层，即 Muse Spark、Claude、DeepSeek 这类底座；编排层，把模糊诉求拆成步骤、决定调哪个工具；执行层，真正在浏览器里替你点、填、下单的那台机器；还有算力层。价格结构在这里出现反差。模型与算力这一层已被打到地板价，每百万 token 的报价低到近乎可忽略，底座还随时能换；而你为「把事做完」付的是按月固定的订阅费。最容易被替换的那一层，恰恰拿不到最稳定的那笔钱。

议价权可能不在最性感的那一层

于是第三问有了倾向。执行层不是租来的能力：Muse 给每个用户单开一台带独立浏览器的安全虚拟机，结账走一次性虚拟卡，要养常驻、有状态、需运维的一摊东西，堆的是固定成本和门槛。以下为判断，不是审计过的分部数据：钱更可能向握着入口的一端集中——装着你的账号、历史对话与支付方式、又能一句话把活派出去的那个 app 层，而非模型层。谁离用户近、谁管着支付与身份，谁就更有议价权。

价值沉淀在哪一层：模型、编排、执行、出口、算力

四个问题分五层

判断价值沉淀在哪一层，只用四个问题：卖什么、按什么计费、门槛在哪、会不会被上下游吞掉。越往下越像固定成本，越往上越像可替换商品：模型按 token，编排按席位，执行按秒还得先买并发额度，出口按浏览器小时，算力按小时批发。本篇只看公开单价与计费口径，不看融资额与估值。

传导次序

次序大致是：出口与执行先收到按秒的账，算力收到订单但价格随行就市，模型层最先被卷成公用事业。

架构总图：从一句话到一台云电脑，中间经过什么

一次真实任务的六个环节（按时间顺序）

  1. 意图进入先过模型网关做路由、鉴权、限流，再进推理集群产出第一个动作。状态只在单次请求内，失败就重新排队，用户端表现为“转圈”。
  2. 规划循环模型把目标拆成工具调用并维护上下文窗口。这层跑在编排框架里，状态存在内存中的对话历史；一旦超窗或工具报错，触发重规划或中断。
  3. 执行环境分配调度器按镜像与快照拉起一个沙箱，冷启动和出网是这里的硬成本。谁提供沙箱池，决定了这一段是自建还是采购。
  4. 环境内的动作沙箱内部执行浏览器操作、shell 命令、读写文件系统，并经代理出网。AgentBay 官方文档覆盖浏览器、云电脑、代码、移动端等沙箱类型。
  5. 状态与产物登录态、下载文件、屏幕录像沉淀进会话上下文与对象存储；会话隔离与可审计是厂商标榜的重点。
  6. 观测与回放截图、trace、审计日志回传给编排层做下一步判断；连接中断时靠回放续跑。

谁负责哪一段：判断依据与边界

整条链路没有任何单一厂商全栈自研。据公开文档，模型与编排层通常自建或采购，真正卡脖子的是安全沙箱与出网生态这两段。开源底座里，gVisor 走用户态内核、Firecracker 走 KVM 微虚拟机，两者官方都把自己定位为“不受信代码 / 多租户”执行场景——这解释了为什么云厂商愿意基于它们封装产品。需要点明：下面“哪些能自建、哪些只能买”是我基于公开文档的推断，除标注外并非厂商明示。

一次中等复杂度任务，算给你看

设定：2 核 4GB 环境运行 10 分钟，模型往返 12 次，每次喂入约 25k token 的截图加历史、产出 300 token 动作。按阿里云口径逐项算：CPU 2×0.12×10/60＝0.04 元，内存 4×0.05×10/60＝0.033 元，token 300k 输入＋3.6k 输出折 5.5 Credits＝0.28 元，回放存储约 0.01 元。合计 0.36 元，执行环境只占两成，模型占七成半。AWS 官方示例算的是同形状会话（10 分钟、80% 等待、2vCPU/4GB），计算部分 0.012267 美元——币种不同，结论一致：环境按「分」计，token 按「角」计，人工那一头按「元」起。

能压的、压不动的

环境这段能压，抓手是「谁为等待买单」。AWS 写明 agent 会话 30%–70% 的时间在等模型或接口返回，v2 把等期间的核时归零、空闲内存 120 秒后回收；AgentBay 反过来在 FAQ 里明确：只要会话没删除就持续计费。这条差异不是会计口径，是架构选择——你要不要为保住登录态养一个长会话。token 这段压的是结构：百炼 Batch 半价、显式缓存命中按标准输入 10% 计费，而 agent 的输入里绝大部分是重复的屏幕历史；DeepSeek 官方把非峰时段定成峰时的一半，重试和跑批值得排到谷时。压不动的是重试本身。OSWorld 369 个真实任务上，人类做成 72.36%，2024 年最佳模型只有 12.24%——把「重跑」当默认策略，那 0.36 元要乘上重试次数，等待同样翻倍。

所以这笔账该怎么读

看多这条链时，别把几分钱的核时当成需求弹性；真正传导到硬件的是推理 token 量和并发会话数。做产品的人反过来：先测重试率，再谈单价。

利好哪些硬件——而且必须区别于 AI 推理服务器

先把两笔钱分开

推理服务器买的是算力本身：GPU、HBM、高速互联、整机柜高功率供电。Agent 执行层买的是通用算力：多核 CPU、内存、企业级 SSD 与快照存储、网卡与 DPU，外加电力和带宽。

判别只看一条：收入随 GPU 出货量走，还是随通用服务器台数与在线实例数走。两者的周期和毛利结构完全不同，混在一张受益名单里必然算错。

为什么先卡在内存和盘上

每开一个会话就要起一套自己的操作系统和浏览器。Chrome 桌面端自 67 版起默认开启 Site Isolation，一个站点独占一个渲染进程；论文实测重负载会话的进程数由 35.0 增至 52.7，整个浏览器内存开销上升 9–13%，页面加载延迟只增加不到 2.25%。沙箱侧同理：Firecracker 论文给出每个 microVM 内存开销低于 5 MB、启动低于 125 毫秒、单机每秒可创建 150 个，存储只挂块设备并按设备限 IOPS。会话数一上去，先紧的是内存和盘的读写次数。

推理侧：随 GPU 出货走

  • GPU、HBM、先进封装、机柜级高功率
  • 营收随单卡价格与机柜瓦数走
  • 起得快，砍单也快

执行层：随实例数走

  • 通用机、RDIMM 内存、企业级 SSD 与快照盘、网卡/DPU
  • 营收随在线实例数与会话时长走
  • 跟 agent 调用量线性增长，毛利接近云资源
液冷与电源两边都要用，不能因为带 AI 字样就划进推理侧。
