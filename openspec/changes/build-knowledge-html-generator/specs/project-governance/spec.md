# Spec Delta

## Purpose

定义跨会话的三项流程行为：可持续追加的开发记忆、改动前必查的红线、以及保持真实的交接台账，使项目被关闭会话或被他人接手后仍能续跑。

## ADDED Requirements

### Requirement: 开发记忆持续追加

项目 SHALL 维护一份追加式的记忆文件，记录当前状态快照、决策记录、环境与踩坑事实、测试日志，供新会话在不询问的情况下恢复上下文。

#### Scenario: 冷启动可续跑

- **WHEN** 一个新会话按指引顺序读取项目文件
- **THEN** 能确定当前阶段、下一步该做什么、以及哪些环境事实不需要重新试错

#### Scenario: 记录真实输出

- **WHEN** 一次测试或探针被执行
- **THEN** 记忆文件中记录命令、实际输出摘要与结论
- **AND** 历史条目不被回改

#### Scenario: 环境事实沉淀

- **WHEN** 发现一个重新发现代价较高的环境事实（图源可达性、CLI 权限行为、失真的遥测字段）
- **THEN** 该事实被写入记忆文件而非只留在会话里

### Requirement: 改动前检查红线

项目 SHALL 维护一份红线文件，并 SHALL 在任何改动前检查是否违反生效红线。默认状态下生效红线集合为空。

#### Scenario: 默认无红线

- **WHEN** 红线文件的生效清单为空
- **THEN** 改动流程正常进行，不因缺少红线而阻塞

#### Scenario: 违反红线时停止

- **WHEN** 计划中的改动会违反某条生效红线
- **THEN** 改动停止并向开发者说明，请求处置方案
- **AND** 不得先执行再补记录

#### Scenario: 候选红线不具约束力

- **WHEN** 红线文件中存在标记为候选、未被开发者确认的条目
- **THEN** 这些条目不被当作规则执行

### Requirement: 台账保持真实

项目 SHALL 维护工作项台账，且每条工作项 SHALL 只存在于一个状态段：完成时从待办移除并追加到已完成（带日期与证据指针）；出现新需求时新增待办项；移除功能时删除对应项并记录原因。

#### Scenario: 完成即迁移

- **WHEN** 一项工作通过全部质量闸门
- **THEN** 它不再出现在待办清单中
- **AND** 已完成清单新增一行，含日期与一个可点开的证据指针

#### Scenario: 开发中新需求

- **WHEN** 开发过程中产生新的需求
- **THEN** 待办清单新增一条独立工作项，而非并入既有项

#### Scenario: 功能被移除

- **WHEN** 某功能被决定不再提供
- **THEN** 对应工作项被删除，且决策记录说明删除原因

#### Scenario: 证据指针可核验

- **WHEN** 一条已完成记录被写入台账
- **THEN** 其证据指针指向具体文件、测试名或命令，而非"已完成"这类无法核验的表述

### Requirement: 并行互斥标记

台账 SHALL 提供"进行中"状态，作为多会话并行时的互斥标记。

#### Scenario: 领取工作项

- **WHEN** 一个会话开始某项工作
- **THEN** 该项被标为进行中
- **AND** 其他会话不会重复领取同一项

### Requirement: 依赖安装遵循镜像优先级

涉及 npm 或 Python 依赖的安装 SHALL 按国内镜像优先、官方源其次、源码编译最后的顺序尝试，并 SHALL 把该策略记录在案。

#### Scenario: 国内镜像成功

- **WHEN** 安装一个 npm 依赖
- **THEN** 使用国内镜像完成安装

#### Scenario: 国内镜像不可用

- **WHEN** 国内镜像缺少该包版本
- **THEN** 回退官方源；若仍不可达，则记录并考虑源码编译，同时把结论写入记忆文件
